# Ctrl-Q Delete: erase to the left

In the measured WordStar Professional 4.00 cases, Ctrl-Q followed by Delete removes the text from the start of the current physical line up to, but not including, the cursor. The cursor moves to the line start. A hard CRLF remains, including when all text before it is removed. Ctrl-U reinserts the removed bytes at the cursor. Ctrl-Q Delete at line start leaves both the document and the previous Ctrl-U content unchanged.

The reference is the primary floppy `WS.EXE`, SHA-256 `535235e6a392d344948d065a5553798e6119b2a0c25ccbaca2221b6b4860904d`. The isolated DOS runs under `C:/Projects/rea/investigations/wordstar/runtime-openstar-ql-01`, `runtime-openstar-ql-lines-01`, and `runtime-openstar-ql-space-01` retain input manifests, ordered keys, screenshots and saved file identities. Each run used a new synthetic document on a copied program disk, with Insert and Align on.

In `LEFT.DOC`, the run typed `ABCDE`, moved to byte offset 2 (L01 C03), and pressed Ctrl-Q Delete. The saved result was `CDE` with EOF padding, 128 bytes with SHA-256 `e0acdbb160bbea2a027a4a989ef7f66433794b88f1021ba81b765203bff0a101`. A second Ctrl-Q Delete at line start made no change. Ctrl-U restored `ABCDE`, SHA-256 `c11c22e6cd0442d059e36d26d5dd9cbc89bff00af0c64f39003fb00a184e7362`.

In `LINES.DOC`, the starting active bytes were `AB` CRLF `CD`. From byte offset 1, Ctrl-Q Delete removed `A` and kept the break and following line, yielding `B` CRLF `CD`, SHA-256 `7e7c79f8489d665f9f4aafdf9e4e8862d440ed06070f6cbc3d35fbf60e0565c7`. Ctrl-U restored the original. From byte offset 2 at the hard break, Ctrl-Q Delete removed `AB` but kept CRLF `CD`, SHA-256 `31e845fdbcf582601412f0c9159a34c321292ca5e428636d00dd177f7c7fb340`. Ctrl-U again restored `AB` CRLF `CD`, SHA-256 `0fe3a6ab58b81269b36891d80377d65a22b008ff5593dedb26331f9f86d95ae2`.

The `SPACES.DOC` run typed `ONE TWO THREE`. WordStar saved high-bit word-end markers in `4F 4E C5 20 54 57 CF 20 54 48 52 45 45`. From the `T` of `THREE` at byte offset 8, Ctrl-Q Delete left `THREE`, SHA-256 `a27318e1371c2cee0602f22451e9ee7d38e4b219ee8b79259f940f037cb4f6bd`. Ctrl-U restored the exact original 128-byte carrier, SHA-256 `7b83835e7375dd40cb51edf024f4ddbd7dc3dc861a7512ac324d9a8c87521a94`.

Eight `ws4-line-left-erasure-v1` scenarios compare these saved hashes, cursor positions, modes and declared formatting with the Rust core and Windows keyboard route. A separate DOS run, `runtime-openstar-ql-reopen-01`, opened an OpenStar-generated `CDE` result and resaved it with the same SHA-256. This checks file interoperability for that result.

OpenStar supports this command on an ordinary physical line of at most 65 cells, in document mode with single spacing, margins 1/65 and justification off. The selected line may contain ordinary one-byte ASCII and high-bit text markers. Soft spaces, controls, framed characters, dot-command lines, malformed EOF payload, unsupported formatting and placed block marks are rejected before mutation. The existing Ctrl-U buffer is retained if Ctrl-Q Delete removes nothing. Repeated Ctrl-U, interaction with Ctrl-Y, Ctrl-T or Ctrl-Q Y after this command, other break types, long lines, marked blocks, second-line deletion, Insert-off mode, and native UTF-8 documents have not been compared with DOS. A native-window pixel check remains untested.
