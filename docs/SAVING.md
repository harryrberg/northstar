# Save behavior and open questions

The DOS reference for this observation is WordStar Professional 4.00, `WS.EXE` SHA-256 `535235e6a392d344948d065a5553798e6119b2a0c25ccbaca2221b6b4860904d`. The isolated synthetic input `SAVE1.DOC` contained `ALPHA`, CRLF, and `1A` padding to 128 bytes. Its SHA-256 was `02b5afce6e9ee881ac58786e73b11f46c91d01c1b8479bc4cc3fd4ef31a99656`. The retained action and file manifests are in the separate local `runtime-northstar-save-01` investigation.

After opening the file, typing `Z` at the start and pressing Ctrl-K S, WordStar stayed in the editor. `SAVE1.DOC` had SHA-256 `bed78444c31fdc472851c0bd7f8afa1677db1687a1fb3c88fdfed022517289b4`. `SAVE1.BAK` had the original input hash. Typing `Y` and pressing Ctrl-K S again produced `SAVE1.DOC` SHA-256 `653676d5ca25122561fc1d786f3b25e4b4a90799dd28e6369c8fa78db06dc5cc` and `SAVE1.BAK` with the previous saved hash. A subsequent Ctrl-K D with no new edit returned to the opening menu; both the document and backup then had the second saved hash. These are observations for this one 128-byte, local-file sequence, not a general save contract.

OpenStar now maps Ctrl-K S to saving the current path and Ctrl-K D to saving before returning to the opening menu. Ctrl-Shift-S opens Save As, which still requires a new path. A new or untitled document prompts for a name when saved. For a legacy file, each same-path save writes its previous bytes to `<stem>.BAK`; for a UTF-8 file it writes `<filename>.bak`. A save without edits also updates the backup, matching the one retained DOS Ctrl-K D observation above. This is a bounded observed behavior, not proof of every WordStar save path.

For an existing file, the desktop session remembers the bytes last opened or saved. It refuses a same-path save if the file is missing, is a symlink or nonregular file, is marked read-only, or its current bytes differ. It stages and syncs both the new document and the previous bytes in the document directory. It then installs the backup and replaces the document. Windows uses `ReplaceFileW` for existing destinations; macOS and Linux use `rename`. A failed write or backup installation does not advance the saved checkpoint. If final replacement fails, the backup contains the prior document bytes. Save As stages the complete new file before publishing it and refuses to overwrite an existing path.

The comparison protects against changes present when OpenStar reads the file. It is not a lock: a second writer can change the file after the final comparison and before replacement. Identical-byte replacements are not detected. The two path changes are not one atomic transaction, and both modes have separate unsaved-draft snapshots, but there is no transaction journal or directory sync. New-file publication and the first backup use hard links from staged files, so a filesystem without hard-link support refuses these saves without publishing an incomplete document. Network and cloud-synced filesystems, symlink races, file metadata beyond basic permissions on non-Windows systems, and failure injection around OS replacement remain unverified. Use Save As to preserve an edited copy after a conflict. These are modern storage rules; the retained DOS observation does not establish them.
