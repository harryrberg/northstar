# Unsaved draft recovery

OpenStar keeps a separate copy of unsaved work in both document modes. This is a modern safety feature, not a reconstruction of WordStar's recovery behavior. On Windows, new copies live in `%LOCALAPPDATA%\OpenStar-Recovery`, outside the MSI installation directory. Other desktop builds use `XDG_STATE_HOME/openstar/recovery` or `~/.local/state/openstar/recovery`. OpenStar also reads and can clear copies from the former NorthStar recovery directory. Each editing session has its own file. Uninstall leaves these files in place.

The first edit that makes a document dirty writes a snapshot immediately. Later changes are written on a two-second timer. A crash can lose changes made since the last completed snapshot. The write stages and syncs a new file before publishing it. Power-loss durability and directory synchronization have not been verified.

Each UTF-8 record contains exact text, cursor byte position, last saved text, source path and its resolved path, plus hashes used to check the record and the source. Existing version 1 records remain readable. Each WordStar record contains the exact current carrier bytes, including padding and opaque controls, last saved carrier bytes, cursor, Insert mode, declared formatting, source path and hashes. Search state, block marks, and the unerase buffer are not restored.

At startup, OpenStar offers the newest valid unsaved copy. F4 on the opening menu offers one again. Opening a particular file checks for a copy associated with that path and document mode. **Restore copy** opens the snapshot without writing the original. If the source still has the bytes from which the draft started, the recovered document keeps that path and an explicit save may replace it under the normal backup and external-change checks. If the source changed or disappeared, the draft opens without a file name and requires Save As. **Later** leaves the copy on disk. **Discard copy** removes only that recovery file. A successful save or deliberate discard of edits removes the active copy. In UTF-8 mode, undoing back to the saved text also removes it.

Records are limited to 16 MiB. The desktop document limit remains 1 MiB for both modes. A scan examines at most 128 recovery files. Malformed files are reported and retained for inspection. Exact path spelling matters when matching a selected file; F4 can still find a copy made under another spelling. Recovery does not write a source file until the user explicitly saves.

Tests simulate interrupted sessions in both modes, exact carrier and text restoration, changed and missing source files, Save As, an empty UTF-8 draft, and malformed records. A WordStar test preserves opaque control bytes on an untouched line while editing another line. Native Windows keyboard automation of the installed 0.1.18 build could not send input because the window did not report a foreground process ID; the app-level keyboard and recovery tests passed. This does not establish a manual GUI test of 0.1.19.
