# Ctrl-N hard return

The bounded `ws4-hard-break-v1` profile covers Ctrl-N with the distributed `CTLNFL=FF` setting. In the retained DOS run, `ALPHA|BETA` followed by an ordinary hard CRLF became `ALPHA 0D 0A BETA 0D 0A` with Insert both on and off. The two 128-byte saved files have the same SHA-256, `e4521231e5564ad8b26c64b3fcf8b08576f508a8b4fa4fa15608fe91fc228e64`. The comparison scenarios are [`hard-break-insert-on`](../tests/oracles/hard-break-insert-on.json) and [`hard-break-insert-off`](../tests/oracles/hard-break-insert-off.json).

The local investigation's `CTRL_N_TRACE.md` and `runtime-ctrl-n-01/observations.json` record the source identities, handler trace, gap-buffer pointers and saved-file hashes. The left gap-buffer pointer stayed at five text bytes while the right side gained `0D 0A`. OpenStar therefore leaves its cursor at byte 5, before the inserted break. This cursor position is derived from the retained buffer state; there is no independent post-command screen comparison. The input and output files were synthetic. The CLI and desktop tests compare the resulting saved carrier, cursor and Insert state, and a saved OpenStar file reopens in OpenStar. Reopening this new result in DOS WordStar has not yet been tested.

The core owns this operation. Enter retains its separate Insert-off behavior: it moves to the next line instead of inserting a break. Ctrl-N inserts a hard break in either Insert mode. The desktop routes Ctrl-N to the core only in legacy mode; UTF-8 documents keep their separate Enter behavior.

The implementation accepts ordinary printable ASCII physical lines of at most 65 characters in document mode, with margins 1/65 and single spacing. It rejects opaque cells, soft or page-marked breaks on the selected line, dot-command lines, unrecognized payload after EOF and unsupported formatting before changing state. The DOS comparison directly covers only the middle of one hard-terminated line. Right-justification state was not retained as a comparison field in the DOS run; the scenarios use the desktop's current setting. Other cursor positions, an unterminated final line, following-line content, and combinations with other commands are implementation extrapolations, not verified WordStar behavior. The `CTLNFL=00` memory experiment used a different paragraph-conversion branch and is not part of this profile.
